CLASS MANAGEMENT REFACTOR NOTES
Admin School Class Detail Split

Tujuan:
- Menjadi acuan refactor fitur class management di area superadmin.
- Memisahkan halaman daftar kelas dari halaman detail kelas agar UI lebih rapi dan scalable.
- Menambahkan domain baru untuk guru mata pelajaran per kelas tanpa merusak fondasi class membership yang sudah ada.

==================================================
LATAR BELAKANG
==================================================

Kondisi saat ini:
- Halaman /admin/classes memuat form create class.
- Halaman yang sama juga langsung memuat assign guru umum ke kelas.
- Halaman yang sama juga langsung memuat enroll siswa ke kelas.

Dampak:
- Halaman menjadi terlalu padat.
- Sulit berkembang saat kebutuhan domain kelas bertambah.
- Sulit memisahkan konteks antara master class list dan operasional satu kelas tertentu.

==================================================
TUJUAN REFACTOR
==================================================

1. Pisahkan halaman daftar kelas dan halaman detail kelas.

2. Pertahankan fitur lama:
- create class
- assign guru umum ke kelas
- enroll siswa ke kelas

3. Tambahkan fitur baru:
- guru untuk mata pelajaran tertentu dalam suatu kelas

==================================================
STRUKTUR HALAMAN YANG DIINGINKAN
==================================================

Halaman 1:
- GET /admin/classes
- Menampilkan:
  - form buat kelas baru
  - list semua kelas
  - tombol Masuk pada tiap kelas

Halaman 2:

- Menampilkan:
  - informasi kelas
  - wali kelas

  - daftar siswa
  - form assign guru mapel
  - form tambah siswa

==================================================
DOMAIN DATA YANG DIREKOMENDASIKAN
==================================================

Tetap gunakan domain lama:
- school_classes
- class_members

Tambahkan domain baru:
- class_subject_teachers

Tujuan pemisahan:
- class_members tetap menjadi membership umum user ke kelas
- school_classes.homeroom_teacher_id tetap menjadi wali kelas
- class_subject_teachers menjadi penugasan guru untuk mapel tertentu di kelas

==================================================
REKOMENDASI DATABASE
==================================================

Tabel baru:
- class_subject_teachers

Kolom minimal:
- id
- school_class_id
- teacher_id
- subject_name
- created_at
- updated_at

Foreign key:
- school_class_id -> school_classes.id
- teacher_id -> users.id

Constraint yang disarankan:
- unique(school_class_id, subject_name)

Catatan:
- Untuk tahap awal, subject_name cukup berupa string.
- Belum perlu membuat master subjects jika kebutuhan mapel belum kompleks.
- Jika nanti domain mapel berkembang, subject_name dapat dimigrasikan ke tabel subjects terpisah.

==================================================
RELASI MODEL YANG DIPERLUKAN
==================================================

Model baru:
- app/Models/ClassSubjectTeacher.php

Relasi utama:
- SchoolClass hasMany ClassSubjectTeacher
- User hasMany ClassSubjectTeacher sebagai teacher
- ClassSubjectTeacher belongsTo SchoolClass
- ClassSubjectTeacher belongsTo User sebagai teacher

ATURAN BISNIS YANG PERLU DIJAGA
==================================================

- Wali kelas tetap berbeda dari guru mata pelajaran.
- Guru mapel harus merupakan user dengan role teacher.
- Subject assignment tidak boleh bentrok untuk mapel yang sama dalam satu kelas.
- Fitur membership umum guru dan siswa tetap dipertahankan.
- Enroll siswa tetap dilakukan per kelas.
- Assign guru umum tetap dipertahankan jika masih dibutuhkan untuk membership dasar.

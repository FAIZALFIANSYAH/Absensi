==================================================
RELATIONSHIPS
==================================================

users
- hasOne student_profile
- hasOne teacher_profile
- belongsTo approver via approved_by
- belongsTo rejector via rejected_by
- belongsToMany school_classes through class_members

student_profiles
- belongsTo user

teacher_profiles
- belongsTo user

school_classes
- belongsTo homeroom_teacher -> users
- belongsTo creator -> users
- hasMany class_members
- belongsToMany users through class_members
- hasMany attendance_sessions
- hasMany materials
- hasMany assignments

class_members
- belongsTo school_class
- belongsTo user

attendance_sessions
- belongsTo school_class
- belongsTo opener -> users
- hasMany attendance_records

attendance_records
- belongsTo attendance_session
- belongsTo student -> users
- belongsTo scanner -> users

materials
- belongsTo school_class
- belongsTo teacher -> users

assignments
- belongsTo school_class
- belongsTo teacher -> users
- hasMany submissions

submissions
- belongsTo assignment
- belongsTo student -> users
- belongsTo grader -> users

approval_logs
- belongsTo user
- belongsTo actor -> users

==================================================
IMPORTANT CONSTRAINTS
==================================================

- users.email must be unique
- student_profiles.user_id must be unique
- student_profiles.nis must be unique
- student_profiles.qr_token must be unique
- teacher_profiles.user_id must be unique
- school_classes.slug must be unique
- class_members should be unique by school_class_id + user_id + member_role
- attendance_records should be unique by attendance_session_id + student_id
- submissions should be unique by assignment_id + student_id

==================================================
DESIGN NOTES
==================================================

- role and approval_status are stored directly in users for simplicity and speed.
- QR identity is better stored as qr_token or encrypted payload, not only as an image file.
- Attendance should be split into session and record:
  attendance_sessions = attendance event per class/date
  attendance_records = scan result per student
- Class relationship should not be stored directly in users.
- approval_logs is optional but recommended for audit trail.
